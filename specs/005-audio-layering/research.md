# Research: Simultaneous Audio Layering

**Feature**: 005-audio-layering
**Date**: 2026-04-20

---

## Constitution Gate: Principle V

**Tension identified**: Principle V states "Only one Parse Level is active at a time. Levels MUST NOT stack or nest during playback. Multi-level simultaneous layering is deferred and will only be introduced as an explicitly scoped feature."

**Resolution**: This IS that explicitly scoped feature. The spec for 005-audio-layering is the ratified introduction of simultaneous layered playback. Principle V's restriction is satisfied — the layering is being introduced via an explicit dedicated feature spec, exactly as the constitution requires.

**Required follow-up**: After this feature is implemented, the constitution's Principle V MUST be amended (via `/speckit-constitution`) to acknowledge that `layered` mode is now a first-class supported mode alongside `single` mode. The "Future Scope" item "Simultaneous multi-level playback" MUST be marked resolved.

**Gate status**: PASS (conditionally — constitution amendment required post-implementation)

## Decision 1: Layered Playback Architecture

**Decision**: Run 4 independent `setTimeout` tick loops in `App.tsx` — one per active level (word, phrase, sentence, paragraph) — all started simultaneously when the user presses Play in layered mode.

**Rationale**: The existing playback loop in `App.tsx` is a simple recursive `setTimeout` pattern. Extending it to N parallel loops is the lowest-risk change: each loop is completely independent, so a crash in one level doesn't affect others. The Web Audio API's scheduler handles any timing drift between levels automatically.

**Alternatives considered**:
- A single unified loop stepping through all levels: simpler state, but harder to give each level its own tempo multiplier; rejected.
- Worker threads: overkill for 4 concurrent timers; Web Audio handles timing natively.

**Tempo per level**: All levels share the `params.tempo` base. However, each level's parse units are naturally longer than the next (paragraph >> sentence >> phrase >> word), so the slower levels simply trigger less frequently because their unit count is lower, not because of an explicit tempo multiplier. No additional per-level tempo control is required.

## Decision 2: Non-Traditional Sounds via Web Audio API (Principle VIII)

**Decision**: Synthesise all non-traditional (nature, city, environment) sounds using `AudioBufferSourceNode` filled with pre-generated noise, shaped by `BiquadFilterNode` chains. No audio files; no external libraries.

**Rationale**: Principle VIII prohibits external audio dependencies. All synthesis must use the native Web Audio API. The key insight is that many environmental sounds (rain, wind, hum) are shaped noise in specific frequency bands. This is achievable with:
- `AudioBuffer` filled with white or pink noise (generated in JS via `Math.random()`)
- `BiquadFilterNode` (lowpass, bandpass, or notch) to shape the frequency content
- `GainNode` envelope for attack/release

**Non-traditional sound catalog — synthesis approach**:

| Sound | Noise color | Filter | Frequency band | Notes |
|-------|-------------|--------|----------------|-------|
| Rain | White | Lowpass | < 600 Hz | Dense, high-energy noise floor |
| Wind | Pink | Bandpass | 100–400 Hz | Slow amplitude tremolo via secondary GainNode |
| Forest | Pink | Lowpass + Notch | < 300 Hz | Sparse, low-energy |
| Ocean | Pink | Lowpass | < 200 Hz | Very slow attack (>1s), very long release |
| Thunder | White | Lowpass | < 150 Hz | Large attack, sharp decay |
| City hum | White | Bandpass | 200–1200 Hz | Medium-density noise, sustained |
| Traffic | Pink | Bandpass | 80–500 Hz | Low rumble |
| Machinery | White | Notch | 400–800 Hz | Industrial texture |
| Cave | Pink | Bandpass | 60–300 Hz | Heavy lowpass, long reverb tail approximated by slow release |
| Campfire | White | Lowpass | < 500 Hz | Irregular gain modulation to simulate crackling |
| Underwater | White | Lowpass | < 200 Hz | Heavy filter, extremely slow LFO |
| Space | Pink | Lowpass | < 100 Hz | Sub-bass hum; very long durations only |

**Pink noise generation**: Generated by filtering white noise through a simple IIR approximation (Voss-McCartney algorithm, pure JS, ~10 lines, no external library).

**Percussive constraint**: None of the above environmental sounds are percussive (attack is always ≥ 50ms). The `percussive: boolean` flag on each `SoundCharacter` will be `false` for all environmental sounds.

## Decision 3: `SoundCharacter` — Unified Sound Type

**Decision**: Replace `InstrumentPreset` with a new `SoundCharacter` interface that covers both oscillator-based presets and noise-based environmental sounds. `InstrumentPreset` is retained in `types.ts` for backward compatibility with the single-level instrument selector, but `SoundCharacter` is used for the layered mode catalog.

**Rationale**: The existing `InstrumentPreset` is oscillator-centric (`waveform: OscillatorType`). Environmental sounds need `waveform: 'noise'` and additional shaping parameters. Extending `InstrumentPreset` with optional noise fields would create a messy union; a clean new interface with a discriminated union approach is cleaner.

```typescript
// Discriminated union: synthesis vs. noise-based
type SoundSource =
  | { source: 'oscillator'; waveform: OscillatorType }
  | { source: 'noise'; noiseColor: 'white' | 'pink'; filterType: BiquadFilterType; filterFreq: number }

interface SoundCharacter {
  id: string
  name: string
  category: 'synthesis' | 'nature' | 'city' | 'environment'
  percussive: boolean
  attack: number
  release: number
  filterCutoff: number  // primary lowpass cutoff for all sources
  filterQ: number
  gain: number
} & SoundSource
```

The `SoundEngine` renders oscillator-based characters exactly as now; for `source: 'noise'`, it creates an `AudioBufferSourceNode` with a pre-generated noise buffer instead of an `OscillatorNode`.

## Decision 4: Harmoniousness via Pitch Quantisation

**Decision**: In layered mode, quantise all computed frequencies to the nearest pitch in C major across 4 octaves (C2–C6). This guarantees consonance between simultaneous layers.

**Rationale**: When multiple tones play simultaneously, small frequency mismatches produce beating and dissonance. Snapping to a musical scale eliminates this. C major (no sharps/flats) is the simplest, most universally consonant choice. The user may select a different root note in a future enhancement; for v1, C major is the fixed default.

**C major quantisation lookup (Hz, 4 octaves)**:
C2=65.41, D2=73.42, E2=82.41, F2=87.31, G2=98.00, A2=110.00, B2=123.47,
C3=130.81, D3=146.83, E3=164.81, F3=174.61, G3=196.00, A3=220.00, B3=246.94,
C4=261.63, D4=293.66, E4=329.63, F4=349.23, G4=392.00, A4=440.00, B4=493.88,
C5=523.25, D5=587.33, E5=659.26, F5=698.46, G5=783.99, A5=880.00, B5=987.77,
C6=1046.50

**Algorithm**: For a raw frequency `f`, find the note `n` in the table above that minimises `|log2(f/n)|` (ratio in cents). This finds the nearest note across octaves.

**Applied only in layered mode**: Single-level mode continues to use continuous (unquantised) frequencies as before.

## Decision 5: Default Gain Hierarchy

**Decision**: In layered mode, the following default gain values enforce the foreground/background distinction required by FR-002:

| Level | Default Gain | Role |
|-------|-------------|------|
| word | 0.70 | Foreground — most prominent |
| phrase | 0.42 | Mid foreground |
| sentence | 0.22 | Mid backdrop |
| paragraph | 0.10 | Deep backdrop |

**Rationale**: Each level is approximately 40% quieter than the one above it (−8 dB steps). This ensures the word layer is perceptibly louder than the paragraph layer by well over 6 dB (it is ~17 dB louder), satisfying SC-002. The simultaneous peak sum (0.70 + 0.42 + 0.22 + 0.10 = 1.44) could theoretically clip, so a master compressor/limiter `DynamicsCompressorNode` is added at the output stage.

**Master compressor settings** (safe defaults): threshold: −3 dB, ratio: 4:1, attack: 3ms, release: 250ms.

## Decision 6: Per-Layer Instrument in AppParams

**Decision**: Add a `layered` sub-object to `AppParams` containing per-level configuration for layered mode. This keeps all AppParams backward compatible (existing configs without `layered` field simply use defaults).

```typescript
export type LayeredLevel = 'word' | 'phrase' | 'sentence' | 'paragraph'

export interface LayeredLevelConfig {
  soundCharacterId: string  // ID from SOUND_CHARACTERS catalog
  gain: number              // 0–1; default per Decision 5
  enabled: boolean
}

// Appended to AppParams:
export interface AppParams {
  // ... all existing fields ...
  mode: 'single' | 'layered'
  layered: Record<LayeredLevel, LayeredLevelConfig>
}
```

**Default assignments**:
- word → `pluck` (synthesis, transient foreground)
- phrase → `pad` (synthesis, sustained mid)
- sentence → `strings` (synthesis, slow backdrop)
- paragraph → `ocean` (environment, deep ambient)

## Decision 7: Backdrop-Safe Sound Character Filtering

**Decision**: Each `SoundCharacter` carries a `percussive: boolean` flag. When a user opens the instrument selector for a backdrop level (phrase, sentence, paragraph), the UI filters the catalog to `percussive === false` only. For the word level, the full catalog is shown.

**Percussive classification of existing presets** (from `instruments.ts`):

| Preset | Percussive? | Rationale |
|--------|------------|-----------|
| default, piano, organ, strings, brass, flute, bass, pad, choir, lead | false | Sustained oscillators |
| pluck | false | Very short release but still a tonal oscillator; not percussive |
| bell | false | Long ring-out; tonal |

All existing 12 presets are non-percussive. Percussive presets (drum, click, snap) are not added in this feature but the flag is in place for future additions.

All environmental sounds are non-percussive by definition (minimum attack 50ms).

---

## Decision 8: UI Changes

**Decision**: Add a "mode" toggle (single / layered) near the existing parse level buttons in `App.tsx`. In layered mode, the Controls panel shows a "Layered Levels" section (below Global) with a mini instrument selector and gain slider for each of the 4 layered levels. The existing "Levels" section (full LevelParams editor) remains visible for reference and for single-mode fine-tuning.

**Rationale**: Keeping both sections visible makes it clear that layered mode has its own instrument/gain settings that are separate from the single-mode LevelParams. The user can switch modes and immediately see how the two parameter sets relate.
